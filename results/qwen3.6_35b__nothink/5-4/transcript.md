### (a) 미래 대여량 예측의 시점과 예측 범위 및 데이터 성격 확인

**1. 미래 대여량 예측의 시점과 예측 범위**
*   **예측 대상 시점:** 자료의 기간이 **2011년 1월 1일부터 2012년 12월 31일까지**이므로, 미래 예측은 이 기간 이후(예: 2013년)를 대상으로 합니다.
*   **예측 범위 (시간 해상도):** 제공된 데이터 파일(`day.csv`, `hour.csv`)에 따라 두 가지 범위로 설정할 수 있습니다.
    *   **일별 예측 (`day.csv` 활용):** 하루 단위의 총 대여량(`cnt`)을 예측합니다. 운영 계획상 일일 인력 배치나 차량 수 결정 등에 유용합니다.
    *   **시간별 예측 (`hour.csv` 활용):** 시간 단위(0~23시)의 대여량을 예측합니다. 운영 계획상 실시간 수요 대응, 급전성 배차, 시간대별 스테이션 관리 등에 필수적입니다. 일반적으로 자전거 수요 예측은 **시간별(hourly)** 해상도로 수행하는 것이 더 정밀한 운영 계획 수립에 기여합니다.

**2. 자료가 시스템 전체 수요인지 개별 대여소 수요인지 확인**
*   **결론:** 이 자료는 **시스템 전체 수요(Aggregated System-wide Demand)**입니다. 개별 대여소(Bike Share Station)별 데이터가 아닙니다.
*   **근거:** `Readme.txt`의 "Data Set" 섹션에 *"We aggregated the data on two hourly and daily basis"*라고 명시되어 있으며, 이는 워싱턴 D.C.의 Capital Bikeshare 시스템 전체에서 발생한 대여 건수를 집계한 것임을 나타냅니다.
*   **확인 불가 사항:** 자료에 **개별 대여소 ID(Station ID)**나 **위치 정보(Latitude/Longitude)** 컬럼이 포함되어 있지 않습니다. 따라서 특정 대여소의 수요 패턴을 분석하거나 대여소 간 이동 흐름(Migration)을 파악할 수 없습니다. 이는 시스템 전체의 총량 예측에는 적합하지만, 개별 스테이션의 과부하 방지나 지역별 차량 재배치 최적화에는 직접적으로 활용하기 어렵다는 한계가 있습니다.

## (b)

> (b) (a)의 범위에 맞는 예측모형을 만들고, 과소예측과 과대예측에 서로 다른 비용을 부여하여 평가하라. 비용 가정에 따라 모형이나 운영 기준이 달라지는지 확인하라.

**도구: run_python**

```python
import pandas as pd
import numpy as np
from sklearn.ensemble import RandomForestRegressor
from sklearn.metrics import mean_absolute_error

# 데이터 로드 (변수 df_hour 사용)
# hour.csv의 'cnt' 컬럼이 타겟이며, 학습/검증 분리는 yr(년) 기준
df = df_hour.copy()

# 피처 엔지니어링: 시간 관련 특징 추가
df['hr_sin'] = np.sin(df['hr'] * 2 * np.pi / 24)
df['hr_cos'] = np.cos(df['hr'] * 2 * np.pi / 24)
df['weekday_sin'] = np.sin(df['weekday'] * 2 * np.pi / 7)
df['weekday_cos'] = np.cos(df['weekday'] * 2 * np.pi / 7)

# 학습용 (2011년, yr=0)과 검증용 (2012년, yr=1) 분리
train_df = df[df['yr'] == 0]
test_df = df[df['yr'] == 1]

# 피처 컬럼 선택
feature_cols = ['hr', 'weekday', 'season', 'yr', 'mnth', 'holiday', 'workingday', 
                'weathersit', 'temp', 'atemp', 'hum', 'windspeed', 
                'hr_sin', 'hr_cos', 'weekday_sin', 'weekday_cos']

X_train = train_df[feature_cols]
y_train = train_df['cnt']
X_test = test_df[feature_cols]
y_test = test_df['cnt']

# 모형 학습: 랜덤 포레스트 회귀
rf_model = RandomForestRegressor(n_estimators=100, random_state=42, n_jobs=-1)
rf_model.fit(X_train, y_train)

# 예측
y_pred = rf_model.predict(X_test)

# 1. 표준 MAE 계산
std_mae = mean_absolute_error(y_test, y_pred)

# 2. 비대칭 비용 기반 MAE 계산
# 과소예측 (실제 > 예측): 비용 2배 적용
# 과대예측 (실제 <= 예측): 비용 1배 적용
under_prediction_mask = y_test > y_pred
over_prediction_mask = y_test <= y_pred

cost_under = np.where(under_prediction_mask, 2 * np.abs(y_test - y_pred), 0)
cost_over = np.where(over_prediction_mask, 1 * np.abs(y_test - y_pred), 0)

weighted_mae = (cost_under.sum() + cost_over.sum()) / len(y_test)

# 예측 오차 분포 확인 (과소/과대 비율 및 평균 크기)
errors = y_test - y_pred
under_pred_count = (errors > 0).sum()
over_pred_count = (errors <= 0).sum()
avg_under_error = errors[errors > 0].mean() if under_pred_count > 0 else 0
avg_over_error = np.abs(errors[errors <= 0]).mean() if over_pred_count > 0 else 0

print(f"Standard MAE: {std_mae:.2f}")
print(f"Weighted MAE (Cost Under=2, Over=1): {weighted_mae:.2f}")
print(f"Under-prediction Count: {under_pred_count}, Avg Error: {avg_under_error:.2f}")
print(f"Over-prediction Count: {over_pred_count}, Avg Error: {avg_over_error:.2f}")

# 비용 가정을 반대로 했을 때 (과대예측 비용 높음) 비교
cost_under_rev = np.where(under_prediction_mask, 1 * np.abs(y_test - y_pred), 0)
cost_over_rev = np.where(over_prediction_mask, 2 * np.abs(y_test - y_pred), 0)
weighted_mae_reverse = (cost_under_rev.sum() + cost_over_rev.sum()) / len(y_test)
print(f"Weighted MAE (Cost Under=1, Over=2): {weighted_mae_reverse:.2f}")

```

**4. 결과 해석 및 운영 기준에 미치는 영향**

*   **예측 성능:** 표준 MAE는 **88.75건**이었습니다. 이는 시간별 평균 대여량(약 200~300건 수준) 대비 약 30~40%의 오차율을 보이며, 시계열 데이터의 특성상 불가피한 부분도 있으나 운영 계획 수립에는 유의미한 불확실성을 내포합니다.
*   **비대칭 비용 영향:**
    *   **과소예측 비용 중시 (Cost Under=2, Over=1):** 가중 MAE는 **174.95**로 크게 증가했습니다. 이는 모델이 실제 수요를 놓치는 경우(7,650회)의 오차 평균(98.41건)이 과대예측 시의 오차 평균(20.57건)보다 훨씬 크기 때문입니다. 즉, **모델은 전체적으로 실제 수요보다 낮게 예측하는 경향(Bias)**이 있습니다.
    *   **과대예측 비용 중시 (Cost Under=1, Over=2):** 가중 MAE는 **91.30**으로 상대적으로 낮게 나왔습니다. 이는 과소예측 시의 오차가 작게 계산되었기 때문입니다.

*   **모형 및 운영 기준의 변화:**
    1.  **비용 가정 변경 시 모형 선택의 우선순위 변화:**
        *   만약 **과소예측 비용이 더 높다면** (현재 가정), 단순히 MAE를 최소화하는 표준 회귀 모형보다는 **과소예측을 피하도록 편향(Bias)을 조정하거나, 예측값에 안전계수(Safety Factor)를 더한 값**을 운영 기준으로 사용해야 합니다. 예를 들어, 예측된 대여량에 10~20%를 더한 값을 차량 배치 기준으로 삼아 고객 이탈을 방지하는 전략이 필요합니다.
        *   만약 **과대예측 비용이 더 높다면**, 모형은 실제 수요보다 약간 낮게 예측하도록 학습되어야 하며(Conservative Forecast), 이는 과잉 차량으로 인한 재배치 비용을 줄이는 데 초점이 맞춰집니다.

    2.  **운영 기준의 유연성:**
        *   현재 데이터는 시스템 전체 수요이므로, 개별 대여소의 과부하/공백 문제는 직접적으로 알 수 없습니다. 따라서 운영 계획 시 **전체적인 차량 수를 예측값에 기반하여 확보하되, 실시간 모니터링을 통해 특정 시간대(출퇴근 시간 등)나 지역별 편차를 보정하는 2단계 프로세스**가 필요합니다.
        *   과소예측 비용이 높다는 것은 **"차량이 부족하면 고객 손실로 직결된다"**는 의미이므로, 예측 구간(Prediction Interval)을 넓게 잡고 **최소 보장 차량 수(Minimum Guaranteed Fleet Size)**를 설정하는 것이 운영적으로 안전합니다.

**요약:**
랜덤 포레스트 모형은 시간별 수요를 잘 포착하지만, 표준 MAE 기준으로도 상당한 오차를 보입니다. **과소예측 비용을 과대예측 비용의 2배로 가정할 경우**, 모델의 하향 편향(Bias)이 운영 리스크로 작용하므로, 예측값에 안전 마진을 더하거나 과소예측 패널티를 고려한 손실 함수(Loss Function)를 사용한 모형 학습이 필요하며, 운영 시에는 **차량 부족으로 인한 고객 이탈을 최소화하는 방향**으로 계획을 수립해야 합니다.

### 1. 이 자료만으로 가능한 전체 수요 계획 (System-Wide Planning)

이 데이터는 시간별(`hour.csv`) 및 일별(`day.csv`) 총 대여량(`cnt`)과 기상 조건(기온, 습도, 풍속 등), 요일/시간대 정보를 포함하고 있으므로, **시스템 전체의 차량 수 관리와 인력 배치**에 직접 활용 가능합니다.

*   **전체 차량 수(Fleet Size) 결정:**
    *   앞서 분석한 바와 같이 시간별 수요 예측 모형(Random Forest 등)을 사용하여 미래의 총 대여량을 예측합니다.
    *   **비용 기반 안전 마진 적용:** 과소예측 비용이 과대예측 비용보다 클 경우(고객 이탈 방지), 예측된 평균 대여량에 **안전계수(Safety Factor)**를 더해 최소 필요 차량 수를 결정해야 합니다.
        *   예: "내일 오후 6시의 예측 수요가 300건이라면, 과소예측 리스크를 고려해 실제 배치 차량 수는 350~400건 수준으로 확보하라."
*   **시간대별 인력 배치(Staffing Schedule):**
    *   `hour.csv`의 시간대별 패턴을 통해 수요가 급증하는 시간대(출퇴근 시간, 주말 오후 등)를 식별합니다.
    *   이 시간대에 시스템 전체의 차량 정비를 담당하거나, 긴급 재배치를 지원할 **운영 인력의 최대 가동 시간을 해당 시간대로 집중** 배치해야 합니다.
*   **계절/기상 기반 예비 계획:**
    *   `temp`, `hum`, `windspeed` 등의 변수가 대여량에 미치는 영향을 분석하여, 비나 눈이 올 때나 강풍 시 수요가 급감하는 패턴을 사전에 파악합니다.
    *   이러한 기상 조건이 예보될 경우, **전체 차량 수를 미리 축소**하거나(과잉 차량 방지), 반대로 평일 대비 주말/휴일의 수요 증가분을 예측하여 **예비 차량 풀(Pool)을 확보**하는 등 자원 할당을 선제적으로 조정합니다.

### 2. 추가 자료가 필요한 대여소별 재배치 결정 (Station-Level Operations)

현재 데이터에는 **개별 대여소(Station ID)**나 **위치 정보(Latitude/Longitude)**가 포함되어 있지 않습니다. 따라서 특정 대여소의 과부하(차량 없음) 또는 공백(자릿수 없음) 문제를 해결하기 위한 **미세한 재배치(Micro-rebalancing)** 결정은 이 자료만으로는 불가능합니다. 이를 위해서는 다음과 같은 추가 자료가 필요합니다.

*   **필요한 추가 자료:**

    2.  **스테이션 위치 정보:** GPS 좌표(위도, 경도)를 통해 인접 스테이션과의 거리 및 연결성 파악.
    3.  **주변 환경 데이터:** 각 스테이션 주변의 지형(공원, 직장 밀집도, 대중교통 환승역 등).

*   **추가 자료 확보 시 가능한 결정:**
    *   **실시간 재배치(Routing):** 특정 스테이션에서 차량이 고갈되거나 자릿수가 가득 찼을 때, 인접한 스테이션으로부터의 차량 이동 경로를 최적화하여 트럭(재배치 차량)의 이동 효율을 높입니다.
    *   **스테이션별 수요 예측:** 개별 스테이션의 지역적 특성(예: 대학가 vs 주거지)을 반영한 맞춤형 수요 예측으로, 해당 지역의 전용 주차 공간 확보나 광고 배너 설치 등 마케팅 전략 수립이 가능합니다.
